# Backlog — Tournaments

- [ ] Guard the date construction in the yearly scheduling branch, and fix the diagnostic page that should catch it. `GenerateStartDays` builds `new DateTime(firstDay.Year, Month.Value, dayOfMonth)` unguarded on the production path, so a template whose month/day pair cannot form a date in the current year — 29 February outside a leap year, or a plain typo like month 2 day 30 — throws `ArgumentOutOfRangeException` out of the iterator. `TournamentSchedulingJob` catches at the top of the job, so the *remainder* of that night's templates is skipped: the symptom is "some tournaments are missing", not "generation stopped", and it repeats identically every night. Nothing validates the fields — `ScheduleType`, `DaysOfWeek` and `DaysOfMonth` are plain strings and `Month` a bare `Int32?` in the WebAdmin entity. The admin page that exists to report broken templates, `TournamentTemplateBreaksModel`, repeats the same unguarded `new DateTime` and `int.Parse` against a hardcoded year 2019, so it throws on such a template instead of reporting it — and being hardcoded to a non-leap year it can never handle a 29 February template at all. Currently unreachable: no yearly template carries an impossible pair, and annual template re-validation plus designer oversight of generation keep it that way, see [content calendar](content-calendar.md). Pre-existing, not introduced by r16495 — which added exactly this guard for the ordering path and left the production path as it was. Surfaced by the FP-46040 review — see [review](../../../review/FP-46040--tournament-qualifier-start-order/review.md) F-4
- [ ] Make `StagesCount` agree with what generation actually streams. `GetTournamentSeriesBasicInfo` counts every template of a serie, with no `IsActive` filter, while `ScheduleTournements` streams only active ones. A serie mixing active and inactive stages therefore never reaches `StagesCount` in `AssignSerieInstanceIds`, `SerieInstanceId` stays null and no instance is created — silently, like the year-edge case. Currently unreachable: of 19 series, 13 are fully active and 6 fully inactive, none mixed. Surfaced by the FP-46040 review — see [review](../../../review/FP-46040--tournament-qualifier-start-order/review.md) F-4

- [ ] Serie spanning the calendar year edge is laid out wrongly or not at all. `GetTournamentSeriesBasicInfo` ranks stages by `Month*44640 + Day*1440 + ...`, so for a December/January serie the January stage always becomes `InitialTemplateId`. `AssignSerieInstanceIds` only starts collecting at that template, so the outcome depends on the date the daily job runs: on most dates the December stage arrives first, `serieContent` never reaches `StagesCount`, `SerieInstanceId` stays null and nothing is created; on a run in the first days of January (or the last of December) the January stage arrives first, the serie completes, and an instance is created with its stages roughly twelve months apart. Both failures are silent — no exception, no log line. Currently unreachable: the designer keeps the year boundary clear, see [content calendar](content-calendar.md). Surfaced by the FP-46040 review — see [review](../../../review/FP-46040--tournament-qualifier-start-order/review.md) F-1
